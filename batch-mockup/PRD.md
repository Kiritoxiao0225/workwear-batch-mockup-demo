# 批量效果图 PRD

版本：v3.0 · 2026-09-14 · 用户已授权正式接入与切换

当前顺序固定为：**需求理解 → 图稿制作与修补 → 上衣效果图**。原 A、B 合为一次需求理解与选路；不再独立调用 B 生成工具计划，也不在生成后回到 B 选择抠图供应商。风险评分退出本轮。旧实验与证据保留，但不再作为本轮架构约束。实际进度只维护在 [PLAN.md](PLAN.md)。

## 目标与范围

从客服原文和全部参考图理解首版制作需求，设计师核对、修改并发起生成后，获得文字、图形、颜色与参考关系正确的独立图稿。减少无必要的模型调用和中间转写。

入口只取 WPS“待领取／未领取”。不额外要求修改次数字段。服装尺码不影响图稿拆分；款式货号、衣色、图稿尺寸与应用位置保留。已有成品返修、简单批量生图模块不在本轮范围。

使用既定的识图、生图、火山高清、美图抠图能力。供应商协议可以研究和复用，不导入旧业务流程、旧分流阈值或像素修补策略。正式环境通过 PostgreSQL、R2 与 WPS 原表连接；模型任务在 Zeabur 常驻后台执行。发布与在线验收状态记录在 PLAN。

## 三阶段职责

| 阶段 | 输入 | 输出与边界 |
| --- | --- | --- |
| 1 需求理解 | 客服原文、全部原图、补图、设计师明确修订 | 一次真实模型调用，直接返回按图稿分块的完整正文、制作方式、素材关联、应用关系及具体识别问题。设计师可以修改、补图、重识别；不进行制作或打分 |
| 2 生图 | 点击生成时固定的逐图稿正文与图片、制作方式 | 生图／高清放大／直接复用；按实际输出需要使用美图去外部背景。没有生图前强制高清、统一白底或供应商智能分流。正式制作由持久队列执行 |
| 3 上衣效果图 | 当前图稿/修补版本、服装目录和位置 | 同款同色同方案的正背面合成一张带框高清PNG；拖动、缩放、自动保存与整图复制，不增加评分模型 |

生图和高清是两种主动处理能力，直接复用是跳过不必要处理。已清晰、仅需去背景的图也允许直接进入抠图环节。是否透明依据实际像素和外部背景，不能只看 PNG、hasAlpha 或棋盘格。美图并非万能：保留已经测出的内部白字丢失等反例，用于后续成品核对。

## 第一阶段的正文样式

用户在首版表格审阅后进一步确定：所有图稿必须固定七项，方便只修改颜色或排版。每张独立图稿只有一份 `prompt`，以位置／版本标题开始，固定按“主体、文字、字体、颜色、排版、尺寸、输出”七项输出，任何简单图稿都不能缺项。沿用原图的颜色、字体或版式时简短说明依据；确未指定尺寸、字体时如实陈述，不猜造数值，也不因此新增缺失提醒。工艺等实际要求归入适当栏目。

素材用途直接写入对应要求；不另写重复的整体目标、素材用途、图稿说明与应用关系。沿用图中 Logo 和文字时引用图号与范围，不再次 OCR 转录。客户明确提供的新增、替换、删除文案保留字符、标点、空格和换行。所有影响结果的条件必须保留，不能为了短而删减。

每个图稿正文独立完整，不写“同上”。同稿用于多个款色时正文只写一次，应用关系单独保存。不同位置或配色版本按实际需求拆分，空白后背字段不产生新任务。字体、颜色、排版参考必须实际绑定，不能把参考图片整体当作内容复制。

模型输出 `artworks[]`：`id/name/route/applications/imageIds/prompt`；以及 `readingIssues[]`。`route` 仅允许 `generate/enhance/reuse`，不输出工具步骤或风险分数。当前真实理解 API 使用已确认的 CLIProxy、`gpt-5.6-sol`、`low`，提示词源文件为 [requirements-prompt.txt](application/requirements-prompt.txt)。

## 前端与逐字交接

表格左列放原文、原图和补图入口，后面是三个阶段。需求理解列七项正文直接点击编辑，不必打开修改弹窗。停止输入约700毫秒或离开该项后保存；页面仅在服务端确认后显示“已保存”，失败保留当前输入并提示。款色、路线和素材关联收在“其他设置”内；不再提供独立“确认要求”按钮、待核对／已确认筛选、确认计数或核对人输入。自动保存只表示正文已持久化，不表示内容正确。

人工新增或替换的文字与其对应模型原稿比较，在结束编辑后以红色加粗显示；删除在对应栏目提示“有删减”。刷新后重新依据持久化的模型原稿与当前正文计算，恢复原文则移除标记。标色、删除提示和HTML均不进入制作正文。只替换被编辑的栏目，其他字句、空格和换行保持原样。

同一条需求串行自动保存，输入期间不重绘编辑区或覆盖光标。响应丢失先回读，若服务器已经保存相同正文则不重写；不同版本冲突保留本页内容并提示核对，不自动覆盖另一页面。存在未保存内容时离开页面会提示。

设计师直接编辑同一个 `prompt` 字符串，并能编辑应用、路线、图片关联，增加或删除误分图稿。保存不调用模型。点击“生成”即采用当前要求：先完成待保存修改，再由服务端固定本次正文、全部有编号原图、实际使用的图片身份、应用关系和 SHA；保存失败则不启动生成。生成期间继续编辑用于下一次制作，不改变已启动任务。本地生成入口及版本固定已实现：`production-input-v1`固定正文和全部原图，独立任务保存原始结果、抠图结果及回执。同一输入重复提交回读已有任务，服务中断后的在途请求标为未知，不自动重复付费。历史确认辅助接口保留兼容，不构成当前页面的操作前置。

交接以每份图稿为单位：`production-input-v1.prompt` 必须与点击生成时固定的 `prompt` 完全相同，包括空格和换行。不得拼接其他图稿或隐藏前后缀。全部源图片及原图号保持固定，`imageIds` 指出该图稿实际引用；实际制作适配时不得通过选取子集造成“图2”变成另一张图片。生图请求按原图号顺序传入全部图片，正文不加前后缀；若补图移除造成编号空缺，停止该任务而不偷偷改图号。

`artwork-input-v2`是历史兼容接口，仍保持`executionEnabled=false`。新版真实请求使用`POST /api/production`；返回任务或图片不等于语义验收通过，成图显示待看图，评分暂未实施。

## 补图、修订与失败

漏传 Logo 时允许设计师补附件，不让模型猜造。补图后需用新版提示词重新识别，保留设计师已保存修订；候选供核对，不覆盖当前正文。素材变化后按新素材重新核对；历史正文与图片记录保留。识别中的并发修改不被返回结果覆盖。

每次请求持久保存请求、原始返回、模型、耗时、图片 SHA 和提示词 SHA。未知付费结果不自动重发；单条失败不影响其他条。缺图、实际冲突等提醒可在人工处理后清除；不把所有空字段变为必填项。生成前校验保存版本、图片身份与图号；缺Logo且无附件则显示阻塞。普通核对提醒继续展示，不一概阻塞独立图稿制作。不恢复独立确认步骤。

## 局部修补

制作结果提供“局部修补”入口，使用同尺寸的抠图前原图和当前结果。保留笔恢复涂抹区域的原图RGBA像素；去除笔仅把所选区域设为透明。不调用模型，不重画文字或改写制作要求，不自动填补全部内部孔洞。尺寸不一致、制作在途或超过1600万像素时停止修补，不擅自缩放对齐。

默认工具改为“补空白”：画笔圈内模式，一次点击恢复圈内可补回的内部空洞，已有不透明图案与圈外像素不改变；可切换“单块空白”，点击空洞恢复连通整块。只复制抠图前原图的RGBA，不涂成固定白色，不编造原图也不存在的像素。与图像外缘连通的区域（包括对角细缝）不填补，提示改用保留笔细修；没有可补像素的点击不计入笔画或保存版本。两种模式均支持撤销、重做、保存和重开。补回的是所选区域的原图内容，用户仍须区分正确留空和误抠空洞。

交互提供可调画笔、适合窗口及25%—400%缩放、拖动画布、原图辅助层、深色／白色／棋盘格背景、撤销／重做和恢复原抠图。辅助层与背景只用于预览，不能进入输出。画笔是手工范围，不会自动吸附主体边缘；经过背景也会恢复背景，细节需放大修补。

“保存修补”另存原生尺寸PNG，更新表格预览与下载。原始制作记录、抠图前原图、原抠图文件及此前修补版本保留；恢复原抠图也作为新修补版本保存。未保存退出有丢弃提示。保存请求固定图片SHA、修补版本与笔画，服务端串行处理并检查版本；重复请求幂等，冲突不覆盖其他页面。文件写入并校验SHA后才显示保存成功，失败保留本页笔画。人工修补不代表模型风险评估或自动验收通过。

API为GET/POST `/api/production/repair`，生产任务目录另存`repair-state.json`和每版笔画回执，原`state.json`不被人工修补覆盖。正式数据通过 batch_documents 与 R2 保存，修补后重新合成所有引用。

## 正式上衣效果图与切换边界（v3.0）

- 一份图稿可以被多款色、多位置引用，不重复制作。同款色的左胸和后背在一张3252×2301带框PNG内呈现。同位置候选分成方案；多位置都有候选且配对不明时，在需求理解中明确对应关系，不擅自配对；衣服区不再重复选择图稿。
- 款色来自正式目录，唯一精确匹配才预选。位置按《效果图制作与质量标准 V1.0》（2026-08-17）由结构点计算，素材库显示与合图同一份规则（`lib/sop-placement.ts`）：位置规则 `sop-v5`（按 134 张人工确认图校准）：左/右胸居中于第三粒扣（门襟最下一粒），未标扣位时按肩线至下摆的比例（Polo 17%、马甲 20%、夹克 22%，约为衣长 29%/33%/35%），T 恤、卫衣、冲锋衣为前领口中心下约9.5厘米；后背按肩线至下摆的比例居中（Polo 21%、马甲 20%、夹克 25%，T 恤按后领至下摆 28%），较高图稿的上沿不高于该款上限且在后领下8厘米以下，卫衣、冲锋衣仍居中于肩点至袖窿底之间；素材库微调偏移记录所依据的规则版本，规则更新时自动换算以保持原位置，换算后不足0.5厘米的清除；袖子距缝合线约0.75厘米并收在正面可见袖宽内；正前面上沿在领口下约8厘米，拉链外套不提供正前面。结构点每款标一次：优先取本色已确认标准，其次取同款其他颜色的已确认标准（与“应用到同款其他颜色”相同的轮廓对齐检查通过才沿用，只读不写库），否则由透明轮廓估算并提示；结构点与系统模板完全一致的“确认”不算校准，按估算处理并提醒重标，确认前列出仍为估算或模板位置的结构点；腋下线识别失败按比例估算并警告。门襟、拉链、口袋、帽子等避让区只做最小移动，无法避开时提醒。尺寸按投影衣身40厘米换算（隐形模特底图的正面投影宽，与SOP示例比例一致），衣身宽取下部躯干透明轮廓，长袖贴身时取腋下躯干宽，最后才用确认腋点。默认左/右胸宽8厘米（越扁越宽，最宽10厘米）、高不超过6厘米，后背宽28厘米（马甲21厘米，单行扁长字到30厘米）、高不超过22厘米（竖版照片、插画逐渐放宽到28厘米），等比缩放且包含文字。客户明确尺寸优先，比例冲突或超出可印区域时提示，不拉伸或暗改尺寸；客户未写尺寸但参考图可见Logo印在衣服上时，需求理解在应用关系中单独记录 `sizeReference`（参考图、Logo宽÷腋下衣身宽、依据），不写进制作正文，合图按比例×40厘米定宽、不作为客户尺寸标注，超出可印范围时退回默认并提醒，设计师可在图稿设置中取消；客户指定尺寸时，尺寸写在该卡片的位置说明里；成品图默认不画标注，设计师在放大编辑中点“显示尺寸标注”后才按SOP 2.2标注“Logo 宽度”（异形或指定高度时同时标注最大高度）。Logo与衣色深浅接近或高饱和撞色时只提醒不改色；Logo超出衣服轮廓时提醒。没有可用衣身依据时保留可调整的比例预览并明确提示未标定，不显示厘米尺寸；客户要求明确厘米尺寸时暂停合成并提示校准。按实际Alpha可见范围合成。
- 衣服选择与位置独立保存，不改制作正文或其他衣服；切换款色保留各款排版，图稿修补后更新所有引用并保留位置。
- 静止显示真正的完整PNG；拖动使用Canvas预览，Sharp保存高清图。保存中或失败时不能把旧图当作新图复制。复制、下载不自动将WPS标为已完成。
- 独立batch_documents保存状态，batch_assets引用R2不可变图片，batch_queue由常驻Zeabur worker执行。费用任务中断不自动重发。模型与已定提示词保持一致。
- WPS读取待领取/未领取，新源变化保存在pendingSource，不覆盖人工稿。显式采用新源后再识别，旧稿保留历史。
- /wps-production换为新页面；/wps-production/legacy保留旧页面、旧API和客户历史。正式状态以PLAN与发布回执为准。
