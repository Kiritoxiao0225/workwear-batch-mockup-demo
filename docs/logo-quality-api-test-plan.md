## 第 5 步：统一评估规则

### 清晰度与尺寸

- 同一个 MediaKit `evaluate-image-quality` 标准版，固定项目：`vqscore`、`blur`、`noise`、`cmartifacts`。
- **2026-09-07 更正**：本计划及历史报告将 standard `blur` 当成越高越清晰，实际同图模糊对照得到当前图 2.56、sigma 4 / 12 模糊图均为 100，方向使用错误。标准版 raw `blur` 越低越清晰；内部清晰度参考值按 `100 - blur` 换算，原始值保留。旧分数原值不能直接和清晰度 80 比较，也不能作为修复优劣排序；对应“均未达标”等历史结论待重新解释。证据：`output/quality-direction-audit-20260907-171404/`。
- `noise` 的方向未在本轮独立校准；`cmartifacts` 按原始字段另列。不得把综合分替代模糊检测。MediaKit CLI 文档与 veImageX 对标准版字段的说明冲突，不能用文档的一句解释代替实际方向验证。
- 保存最终原生尺寸 PNG 的白底评分，用于记录是否达到 **80**。不得为达到 80 反复改变输出尺寸、评价区域或锐化参数。
- 另准备 **1016×864 的统一白底评估画布**进行横向比较：保留输入画布比例，用同一固定缩放规则，不做单独锐化、降噪或针对不同供应商的美化。映射/裁剪参数写入记录；比例或排版改变先记保形失败。
- 历史 47.62 是旧输入原尺寸分；统一画布重新评估的原图基线另列，不直接与旧分数算提升百分比。原生尺寸分与统一画布分不得混在同一排行榜。
- 统一画布与原生尺寸完全一致时，以图片哈希复用评分。总评分请求上限见 manifest；预算不足先评估原图和三条首轮候选，追加候选降级为待评分。
- 若明显干净的矢量图与评分严重冲突，记录“评分适用性待核实”，保留 80 标准和未通过状态；禁止自行改公式或宣布模型不适合 Logo 来放行。

### 图形正确性（每项必须通过）

| 项目 | 验收方式 |
| --- | --- |
| 中文与 Logo | “筑屋匠”、上方四块标识和 ® 逐项核对；无增删、变字、笔画粘连或断裂 |
| 轮廓 | 对齐看直线、尖角、圆环和文字内孔；400% 细节图检查波浪边、过圆角和白边 |
| 颜色 | 比较原图可靠主色区域的 RGB/色差及色块内杂色；没有品牌标准色，只能称为相对原图的保真，不能称恢复官方品牌色 |
| 透明度 | 黑底、白底和当前衣服色三种背景对照；无漏背景、漏字、白晕或黑描边 |
| 使用尺寸 | 单独记录有效主体像素与任务 10cm 放置尺寸；300 PPI 对应宽约 1181px 仅为内部素材参考，不把写 DPI 元数据当成增加细节 |
| 上衣可用性 | 按当前任务真实服装和位置生成一次本地预览，检查实际显示大小与小字；不更新任务确认状态 |

若供应商只返回较小图片，保留实际尺寸并标记限制。效果图预览可用、高清源素材可用、印花工艺验收是不同结果，分别记录。

## 第 6 步：费用、失败与停止条件

**全轮新增供应商消费上限 1 元人民币**，包含修复、矢量化、抠图、评分、格式下载及必要的存储/传输费用。此前已发生的试验费用不重复计入本轮。

- 先查询真实接口单价、倍率、最低计费单位和免费额度，再逐次预留费用。veImageX 控制台已确认综合增强倍率 90，执行时仍核对基础单价。
- 美图抠图价格不代表修复价格；Vectorizer 预览/测试水印结果不参加最终评分与胜负评定。
- 有免费额度即可使用。不要为了完成对比自动购买超过 1 元的最低套餐。美元价格按执行时可核实的汇率保守预估，并保留误差余量。
- 每次调用写 `ledger.jsonl`：路线、操作、输入哈希、参数哈希、预估费用、请求 ID、状态、耗时、输出哈希；不写 AK/SK、Bearer Key 或带签名的临时地址。
- 超时先查询任务/已有输出。费用或实际状态不明时，预留金额不释放，不盲目重试。明确未受理的网络错误至多重试一次，仍计入调用和预算上限。
- 达到 1 元、必需权限被拒或全部已配置路线完成后停止付费调用。单家失败隔离，继续可执行的其他项。
- 若三家不能全部实测，报告标明“部分完成”和每家缺项；不得产生完整选型结论。
