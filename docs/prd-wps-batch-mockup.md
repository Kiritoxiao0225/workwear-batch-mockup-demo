## 1. 产品定义

系统从 WPS 接收客户需求原文与附件，把每条需求拆成可独立处理的定制单元，先确认服装位置与制作方案，再制作并确认透明背景的完整素材图，最后将已确认素材图确定性合成到 2208 茶绿色服装上。

系统面向批量生产设计。每个定制单元可以独立分析、执行、失败、重试和确认；一个单元异常不能阻塞其他单元。

## 2. 产品目标

### 2.1 核心目标

- 完整保留 WPS 需求原文与原始附件。
- 自动拆解每个视图、位置和版本所需的素材图与准确文字。
- 在制作素材图之前，用占位框明确显示服装上的目标位置。
- 用明确、唯一的规则选择确定性制作或 GPT Image 2。
- 先得到独立于服装的完整透明素材图，经人工确认后再贴到服装。
- 支持批量执行、进度恢复、单项重试、成本统计和结果导出。
- 任何结果都能追溯到原文、附件、制作文案、位置、调用记录和人工确认。

### 2.2 本期不做

- 根据 WPS 款式原文检索不同服装。
- 自动切换服装款号或颜色。
- 让生成模型直接生成衣服、模特、穿着场景或最终效果图。
- 根据低清或缺失素材猜测客户原稿。
- 自动跳过人工确认并交付结果。
- 提供复杂的图层编辑、自由绘制、蒙版涂抹或专业设计软件能力。

### 2.3 当前服装约束

- 所有任务统一使用 2208 茶绿色 Polo 衫。
- WPS 中的款式描述继续作为原始证据保存，但本期不参与服装选择。
- 当前服装资产同时包含正面与背面。
- 后续接入更多真实服装时，每个款号、颜色和视图必须单独建立位置模板。

## 3. 核心概念

### 3.1 WPS 源记录

一条 WPS 源记录至少包含：

- 稳定记录 ID。
- 客户或任务标识。
- 款式需求原文。
- 制作需求原文。
- 原始附件列表。
- 源记录更新时间或版本。
- 同步时间与同步结果。

WPS 原文是不可改写的事实源。系统产生的理解、摘要和制作文案必须另存，不能覆盖原文。

### 3.2 原始附件

每个附件保存：

- 稳定附件 ID。
- 固定图号，例如图1、图2。
- 原始文件名、URL 与文件哈希。
- 格式、宽高、文件大小和可访问状态。
- 清晰度、透明通道与主体有效区域检查结果。

附件图号在同一源记录中必须稳定。同步或页面排序不能改变“图1”等引用的实际文件。

### 3.3 附件角色

一张附件与一个定制单元之间可以建立以下一种或多种使用关系：

- 内容素材：其中的主体、标识、徽章、图形、文字或完整设计需要进入成品。
- 风格参考：只参考字体、字形、颜色关系、层级、构图或排版，不直接作为成品元素。
- 不使用：与该定制单元没有任何使用关系，并且与前两种关系互斥。

同一附件只有在原文明确要求时，才可以同时作为内容素材和风格参考；两种用途必须分别写清取用内容和参考范围。同一附件在不同定制单元中可以拥有不同角色，但每次角色判断都必须保存 WPS 原文证据或人工修正记录。

### 3.4 素材取用方式

内容素材还要明确取用范围：

- 整张素材。
- 仅主体。
- 主体与内部结构。
- 裁剪指定区域。
- 自定义文字描述的范围。

制作文案必须明确保留项、删除项、裁剪项、改色项和需要新增的准确文字。不能把一张包含背景、装饰和文字的附件自动当成完整成品。

### 3.5 定制单元

最小生产粒度为：

WPS 源记录 × 目标视图 × 目标位置 × 版本

拆分示例：

- 图1放左胸、图2放后背：拆成两个定制单元。
- 图1和图2各出一版左胸：拆成两个版本。
- 同一版本需要正面和背面内容：分别制作素材图，最终合成到同一效果图成品。

每个定制单元独立拥有制作文案、素材角色、位置、路线、执行状态、尝试记录和确认状态。

每个定制单元必须显式绑定稳定的“效果图版本 ID”。不能从单元名称临时猜测归属；同一件衣服的正面、背面和袖部单元绑定同一个效果图版本，不同衣服方案或“各出一版”绑定不同效果图版本。

### 3.6 效果图成品

效果图成品的聚合粒度为：

WPS 源记录 × 服装方案 × 版本

同一效果图版本下所有必需定制单元的素材图均确认通过后，才能合成该版本的完整效果图。正面、背面等位置不能分别生成客户交付图，必须一次性放到同一张正反面画布中。某个版本未满足条件时，只阻塞该版本，不影响批次中的其他版本。

同一 WPS 源记录中如果同时包含不同服装方案，即使本期暂时都使用 2208 茶绿色底图演示，也必须分别建立效果图版本，不能因为底图相同而错误合并。

### 3.7 批次

批次是一组 WPS 源记录和定制单元的执行容器，用于统一同步、筛选、发起、查看进度、重试、确认、核算成本和导出。

批量生产不等于把多条需求合并成一次模型调用。

## 4. 不可变业务规则

1. 原文和原始附件始终可见、可追溯，不被 AI 结果替代。
2. 当前所有效果图固定使用 2208 茶绿色服装。
3. 先确认制作方案和位置，再制作完整素材图。
4. 先确认完整素材图，再合成服装效果图。
5. 顶层制作路线只有“确定性制作”和“GPT Image 2”两种。
6. MediaKit、文字渲染和素材组合是确定性制作中的操作步骤，不是额外路线。
7. 明确参考字体、字形、版式、层级或排版时，优先进入 GPT Image 2。
8. 素材清晰、文字简单不能覆盖明确的字体或排版参考要求。
9. 低清不是进入 GPT Image 2 的理由；可修复则修复，不可修复则阻塞。
10. 每次 GPT Image 2 调用都必须直接要求透明背景 PNG。
11. GPT Image 2 透明结果不合格时只能重试或转人工，不能静默去底后标记成功。
12. 一个定制单元失败不能阻塞同批其他单元。
13. 人工确认只对确认时的输入指纹有效；相关输入改变后自动失效。

## 5. 端到端流程

### 5.1 同步 WPS

1. 服务端读取源记录原文和全部附件。
2. 生成包含原文、附件顺序和源版本的完整快照。
3. 下载或读取附件，计算文件哈希并固定图号。
4. 验证记录和附件数据边界。
5. 同步成功后才替换该记录的上一次完整快照。

同步失败或响应不完整时：

- 不用空数据覆盖已有完整记录。
- 保存具体错误和失败时间。
- 允许只重试同步失败的记录。

### 5.2 拆解需求

系统从原文中提取：

- 目标版本。
- 目标视图。
- 目标位置。
- 各位置使用的内容素材。
- 仅作参考的附件。
- 需要保留、删除、裁剪或改色的内容。
- 必须出现的准确文字。
- 文字颜色、大小、方向、对齐、弧形和层级要求。
- 是否明确要求参考某张图的字体、字形、版式、层级或排版。
- 需要分别出图还是组合出图。

每个判断必须同时保存：

- 结构化结果。
- 对应的 WPS 原文片段。
- 判断置信状态。
- 人工修正记录。

影响素材、文字、位置或版本关系的内容无法确定时，定制单元进入待补充状态，不自动制作。

### 5.3 生成效果图制作文案

每个定制单元生成一份可直接执行的制作文案，至少包括：

- 使用的附件图号。
- 每张附件的角色。
- 内容素材的取用方式。
- 保留、删除、裁剪、抠图、放大和改色要求。
- 准确文字及其样式。
- 参考字体或版式的原文证据。
- 目标视图、位置和占位框。
- 顶层制作路线。
- 路线原因。
- 输出必须为完整独立素材图。

制作文案是结构化执行说明，不是营销文案，也不能补充原文没有的客户要求。

### 5.4 显示位置占位框

1. 页面显示 2208 茶绿色服装。
2. 根据目标视图和位置读取位置模板。
3. 在服装上显示对应占位框和位置名称。
4. 用户可以对占位框进行轻量移动和缩放。
5. 保存归一化坐标与模板版本。

### 5.5 方案确认

用户确认：

- 原文拆解是否正确。
- 附件角色是否正确。
- 素材取用范围是否正确。
- 准确文字与参考要求是否正确。
- 位置和占位框是否正确。
- 制作路线及理由是否正确。

无歧义单元可以在列表中批量确认；存在歧义的单元必须逐项修正。

### 5.6 制作完整素材图

系统根据第 7 节的路线决策执行：

- 确定性制作路线。
- GPT Image 2 路线。

无论采用哪条路线，输出都必须是独立于服装的完整素材图，不得包含衣服、人物、场景或展示底板。

### 5.7 素材图自动检查

结果至少检查：

- 文件可读取。
- 尺寸和格式有效。
- 主体不为空。
- 透明区域有效。
- 可见内容没有被全部裁掉。
- 输出与当前制作配方指纹一致。

自动检查通过不等于人工确认。

### 5.8 素材图确认

页面同时展示：

- WPS 原文。
- 原始附件。
- 制作文案。
- 路线和路线证据。
- 透明棋盘格上的完整素材图。
- 本次执行记录。

用户确认图形、文字、颜色、字体、排版和透明背景均正确后，素材图状态变为已确认。

### 5.9 合成服装效果图

1. 收集同一源记录、同一版本下所有已确认素材图。
2. 根据各自已确认的位置坐标进行确定性合成。
3. 在同一画布中同时展示该版本服装的正面和背面；所有正面、背面和袖部素材只出现于其确认位置。
4. 每个效果图版本只生成一张客户交付图，不能按定制单元生成“另一面空白”的局部效果图。
5. 只允许缩放、旋转和位置模板预先定义的变换。
6. 不调用生成模型重新解释素材图、文字、排版或位置。
7. 输出保持服装资产的原始画布尺寸。

本期不提供自由透视编辑。需要贴合修正时，只能使用该位置模板中事先校准并版本化的确定性参数。

### 5.10 最终检查与导出

- 用户查看同一画布上的完整正反面服装效果图。
- 用户可以通过或退回对应版本。
- 退回时注明需要修改的定制单元。
- 每个通过版本只导出一张客户效果图；独立透明素材图和映射清单作为内部留档，不作为多张局部效果图发给客户。

最终查看属于交付检查，不增加新的素材制作路线，也不能替代前面的两道确认门。

## 6. 服装位置方案

### 6.1 标准位置

当前固定服装使用一次人工校准的位置模板，不调用模型。

每个模板至少保存：

- 服装资产 ID。
- 服装文件哈希。
- 目标视图。
- 位置名称。
- x、y、width、height 归一化坐标。
- 可选旋转角。
- 可选预校准变换参数。
- 模板版本。
- 校准人和校准时间。

标准位置包括：

- 正前面。
- 左胸。
- 右胸。
- 后背。
- 左袖。
- 右袖。

左、右始终以穿着者视角定义，不能随图片朝向或操作者视角改变。单独写“正面”或“正前面”时，按正前面标准位置处理，不得猜成左胸或右胸，也不得仅因没有细分胸位而标记为歧义；原文明确写“正面左胸”或“正面右胸”时，按更具体的胸位处理。超出以上标准位置的正面描述才进入人工确认或条件启用 Grounding。

模板必须绑定服装文件哈希。服装文件发生变化时，原模板自动失效并要求重新校准。

标准位置单次定位成本为 0。

### 6.2 非标准位置

原文描述无法映射到标准模板的位置时，可以条件启用火山引擎 Visual Grounding：

1. 输入 2208 服装图和位置描述。
2. 模型返回 bbox。
3. 校验 bbox 数量、顺序和坐标范围。
4. 将模型返回的 0 至 999 坐标换算成归一化坐标。
5. 在页面显示建议框。
6. 用户确认或修正后才能使用。

模型输出永远只是建议，不能自动通过位置确认。

### 6.3 候选模型与价格

- 候选能力：火山引擎 Visual Grounding。
- 官方示例模型：doubao-seed-2-1-pro-260628。
- 在线推理公开价格：输入 6 元/百万 tokens，输出 30 元/百万 tokens。
- 价格核对日期：2026-09-02。
- 实际费用以火山引擎账单为准。

官方资料：

- Visual Grounding：https://www.volcengine.com/docs/82379/1616136?lang=zh
- 模型价格：https://www.volcengine.com/docs/82379/1099320?lang=zh

### 6.4 启用条件

- 标准位置：禁止调用 Grounding。
- 非标准位置：允许调用 Grounding。
- Grounding 不可用或结果无效：回到人工放置建议框。
- 只有实际启用 Grounding 时，才要求进行该服务的真实接口验收。

## 7. 制作路线

### 7.1 顶层路线

系统只允许以下两个顶层值：

| 路线 | 适用条件 | 输出 |
| --- | --- | --- |
| 确定性制作 | 没有明确字体或版式参考，现有素材与文字工具足以完成 | 透明背景完整素材图 |
| GPT Image 2 | 明确参考字体、字形、版式、层级或排版，或明确要求现有文字工具不支持的艺术文字效果 | 透明背景完整素材图 |

素材缺失、不可读取或无法可靠恢复属于阻塞状态，不是第三条路线。

### 7.2 决策顺序

按以下顺序判断，命中后停止：

1. 检查完成该单元必需的原文和附件是否齐全。
2. 检查内容素材是否可直接使用或可由 MediaKit 可靠修复。
3. 如果无法可靠修复，进入待补充状态。
4. 检查是否明确要求参考字体、字形、版式、层级或排版。
5. 检查是否明确要求确定性文字工具不支持的艺术文字效果。
6. 命中第 4 或第 5 项，选择 GPT Image 2。
7. 其他情况选择确定性制作。

### 7.3 优先级规则

当一个单元同时具备“清晰图片＋简单文字”和“明确参考某张图的字体或版式”时，必须选择 GPT Image 2。

路线取决于制作要求，不取决于图片清晰度。

GPT Image 2 路线必须记录以下任一证据：

- 触发参考要求的准确 WPS 原文片段。
- 人工明确指定的参考关系。
- 明确超出文字工具能力的要求及对应能力代码。

没有证据时，系统不能主观选择 GPT Image 2。

### 7.4 语义区分

- “使用图4的校徽”：图4是内容素材，不触发 GPT Image 2。
- “字体参考图4”：图4是字体参考，触发 GPT Image 2。
- “排版按照图4”：图4是版式参考，触发 GPT Image 2。
- “图1太模糊”：先尝试 MediaKit，仍不可用则阻塞，不触发 GPT Image 2。

### 7.5 路线案例

| 原文含义 | 顶层路线 | 执行方式 |
| --- | --- | --- |
| 清晰徽章放左胸 | 确定性制作 | MediaKit 处理后输出 |
| 清晰图形加普通红色文字 | 确定性制作 | MediaKit＋文字渲染＋确定性组合 |
| 只有普通弧形文字 | 确定性制作 | 文字渲染 |
| 使用完整清晰成稿 | 确定性制作 | 必要格式处理，不重绘 |
| 字体参考图2 | GPT Image 2 | 将内容素材与图2作为所需输入 |
| 排版和层级参考图3 | GPT Image 2 | 生成完整独立素材图 |
| 指定复杂手写艺术字 | GPT Image 2 | 生成完整独立素材图 |
| 内容图低清且无法恢复 | 不分配路线 | 状态设为待补充并索要清晰素材 |

## 8. 确定性制作路线

### 8.1 操作步骤

确定性制作可以按需组合以下操作：

1. 火山引擎 AI MediaKit 抠图。
2. 火山引擎 AI MediaKit 裁剪。
3. 火山引擎 AI MediaKit 无损放大或清晰化。
4. 格式和色彩空间转换。
5. 主体或指定范围改色。
6. 普通文字渲染。
7. 弧形文字渲染。
8. 图形与文字确定性组合。
9. 透明 PNG 导出。

这些操作只是同一路线中的步骤，不创建组合路线名称。

### 8.2 简单文字能力边界

确定性文字工具支持：

- 准确文字内容。
- 已有字体库中的字体。
- 字号。
- 颜色。
- 字重。
- 字距和行距。
- 水平或垂直对齐。
- 直线排列。
- 弧形排列。
- 固定角度旋转。

原文要求参考特定图片中的字体、字形或整体排版时，即使文字内容很简单，也不能使用本路线完成整个单元。

### 8.3 输出要求

- 输出完整素材图，而不是零散组件。
- 默认 PNG。
- 具备有效透明背景。
- 保留必要内部结构。
- 不包含未要求的背景、装饰或文字。
- 不改变原文未要求改变的颜色和比例。

## 9. GPT Image 2 路线

### 9.1 服务合同

- 接入平台：EvoLink。
- 创建接口：POST https://api.evolink.ai/v1/images/generations
- 模型：gpt-image-2。
- 分辨率：1K。
- 质量：low。
- 生成数量：1。
- 背景：transparent。
- 结果格式：PNG。
- 执行方式：异步 task ID，支持查询与 HTTPS 回调。

图片比例根据该单元的完整素材构图选择，不使用服装画布比例强迫素材构图。

### 9.2 每次调用必须显示的规格

每个 GPT Image 2 单元在列表、详情、请求记录和人工确认页都必须显示：

- GPT Image 2。
- 1K。
- Low。
- 透明背景 PNG。
- 触发本路线的原文证据。
- 输入附件及其角色。
- 当前尝试次数。

### 9.3 每次提示词必须包含

- 生成一个单独、完整、独立的服装定制素材。
- 直接输出透明背景 PNG。
- 背景像素 alpha 为 0。
- 不生成白色背景、彩色背景或渐变背景。
- 不生成衣服、人物、模特、场景或展示板。
- 不生成地面、投影或环境阴影。
- 内容素材必须进入成品。
- 风格参考只能影响明确要求参考的字体或版式，不得作为成品元素复制。
- 准确文字必须逐字保留。

透明背景不能只依赖服务端默认值，必须同时出现在 API 参数与提示词中。

### 9.4 输入规则

- 只传当前单元实际需要的内容素材和参考素材。
- 输入顺序和 WPS 图号映射必须记录。
- 图片 URL 必须能被 EvoLink 直接访问或下载。
- 支持格式以官方接口为准。
- 输入超过服务限制时立即报错，不能静默丢弃附件。
- MediaKit 可以在调用前处理输入素材，但不会改变顶层路线。

### 9.5 透明 PNG 自动验收

结果进入人工确认前必须满足：

- 文件可下载且能正常解析。
- 实际格式为 PNG。
- 存在 alpha 通道。
- 背景区域存在有效透明像素。
- 可见主体面积不为空且不过小。
- 主体没有明显被裁断。
- 不包含衣服、人物、场景或展示底板。
- 结果属于当前配方版本。

供应商将透明背景标记为 Preview，但本产品仍直接要求生成透明 PNG。

透明验收失败时：

- 当前尝试标记失败。
- 允许按同一配方重新调用 GPT Image 2。
- 达到重试上限后转人工。
- 不能静默调用 MediaKit 去底并把结果标记为成功。

### 9.6 异步任务

- 发起请求前先保存本地 attempt ID、请求摘要、输入哈希、配方哈希、创建时间和费用预估。
- 收到创建响应后立即保存供应商 task ID。
- 回调丢失时使用 task ID 主动查询。
- 已取得 task ID 后发生超时，按原 task ID 查询，不再次付费提交。
- 创建请求超时且没有取得 task ID 时，状态设为“提交结果未知”，禁止自动重新提交。
- “提交结果未知”必须通过供应商任务记录、控制台或人工对账确认；无法确认时保持等待，只有人工明确授权后才能再次提交，并记录潜在重复费用风险。
- 结果完成后立即下载到自有对象存储。
- 对象存储写入后进行字节读回与哈希验证。
- 较早配方版本返回的结果不能覆盖当前版本。
- 保存最终 usage、实际费用和供应商状态。

### 9.7 费用

gpt-image-2 按文本输入、参考图输入和图片输出 token 计费，费用受比例、分辨率、质量和参考图数量影响。

产品要求：

- 发起前读取供应商报价或估算结果。
- 批次中展示预计费用。
- 完成后记录每次尝试的实际 usage 和费用。
- 不把某个示例单价写成永久固定价格。

官方资料：

- 产品与价格：https://evolink.ai/gpt-image-2
- API 参数：https://evolink.ai/docs/cn/api-manual/image-series/gpt-image-2/gpt-image-2-image-generation
- 任务查询：https://evolink.ai/docs/cn/api-manual/task-management/get-task-detail

## 10. 两道确认门

### 10.1 确认门 A：方案与位置

确认对象：

- 原文拆解。
- 附件角色。
- 素材取用方式。
- 准确文字。
- 参考要求。
- 目标视图和位置框。
- 顶层路线与证据。

通过后才能制作完整素材图。

### 10.2 确认门 B：完整素材图

确认对象：

- 内容是否正确。
- 图形是否完整。
- 文字是否准确。
- 字体和排版是否符合要求。
- 颜色是否正确。
- 透明背景是否有效。
- 是否可以贴到服装。

通过后才能合成服装效果图。

### 10.3 批量确认

- 确认门 A 可以批量确认所有无歧义且已查看制作文案的单元。
- 确认门 B 只能批量确认当前筛选范围内已实际加载并查看的素材图。
- 页面不能在后台自动确认未展示结果。
- 自动检查通过不能替代人工确认。

### 10.4 确认失效

- WPS 原文或附件变化：A 失效并重新拆解；随后重新计算素材 recipe。
- 附件角色、取用方式、准确文字、参考要求、顶层路线或其他素材 recipe 字段变化：B 失效。
- 原文重新拆解后素材 recipe 未变化：B 可以保留，不能仅因原文快照版本变化而重复付费制作。
- 素材图重新制作或替换：B 失效。
- 位置改变：A 中的位置确认和最终效果图失效；若素材 recipe 未变，B 可以保留。
- 服装资产哈希改变：位置确认和最终效果图失效。
- 只修改批次名称或备注：确认不失效。

每次失效都保存原因、时间与触发字段。

## 11. 批量生产

### 11.1 批次结构

批次包含：

- 多条 WPS 源记录。
- 每条记录的多个定制单元。
- 每个“服装方案 × 版本”的单张效果图成品。

每个定制单元保存独立状态，不共享错误或重试次数。

### 11.2 执行通道

设置两个队列通道：

- 确定性通道：MediaKit、文字渲染、素材组合和服装合成。
- GPT 通道：EvoLink GPT Image 2 异步任务。

两个通道分别配置并发上限、超时、速率限制和重试策略。具体数值根据真实账户配额和压力测试设置。

Grounding 属于方案确认前的位置准备服务，不是素材制作路线。条件启用时，它使用独立的服务并发限制和调用记录，但不增加第三个顶层制作路线。

### 11.3 幂等

完整素材图的 recipe hash 由“公共业务指纹＋路线专属执行指纹”组成。

公共业务指纹至少包含：

- 从 WPS 原文中提取的、与素材制作有关的规范化字段及对应证据片段哈希。
- 按固定图号排序的附件使用元组；每个元组包含附件 ID、图号、文件哈希、角色和取用方式。
- 准确文字及其明确样式要求。
- 制作文案中的素材制作部分，不包含目标位置与占位框。
- 顶层路线。
- 路线规则版本。
- 输出格式和透明背景要求。

确定性制作的执行指纹至少包含：

- MediaKit 操作顺序、操作参数和服务或适配器版本。
- 使用的字体文件哈希。
- 文字渲染器版本和参数。
- 素材组合器版本和参数。

GPT Image 2 的执行指纹至少包含：

- provider 和 model。
- size、resolution、quality、background 和 n。
- 最终提示词哈希与提示词模板版本。
- 按模型输入顺序保存的 WPS 图号、用途和实际输入文件哈希。
- 存在输入预处理时的 MediaKit 操作指纹。

每个预处理步骤先以“输入文件哈希＋操作参数＋执行版本”计算 step hash，再执行或复用结果。步骤输出哈希只保存为该步骤的 result provenance，并作为下一步骤的输入哈希，不能反向进入创建它自身的 step hash。全部输入准备完成后，再计算后续素材制作或 GPT 提交的幂等键。

自动验收另设 validation fingerprint，至少包含待验收结果文件哈希和验收规则版本。验收规则升级时优先重新检查已有结果，不能仅因验收规则变化而重新执行付费制作。

只有在供应商文档和真实调用均确认支持幂等键或 client request ID 后，才能把本地幂等键发送给供应商并依赖它防止重复创建。在此之前，本地 recipe hash 不能被当成供应商侧未创建任务的证据。

完整 WPS 原文快照只用于事实追溯，不整体写入素材 recipe hash。原文变化后必须重新拆解；重新计算得到的素材 recipe 未变化时，不重复制作素材图。

服装视图、位置和占位框不进入素材 recipe hash。

最终效果图的 compose hash 至少包含：

- 服装资产哈希。
- 按稳定顺序排列的定制单元映射元组；每个元组同时包含定制单元 ID、素材图哈希、目标视图、位置 ID、位置坐标、位置模板版本和确定性变换参数。
- 服装合成器版本。
- 输出规格。

所有元组使用定义好的规范化序列化方式后再计算哈希，不能分别对无序集合求值。

相同 hash 已有合格结果时可以复用。

### 11.4 重试

- 只重试失败单元。
- 确定性操作按失败步骤重试。
- GPT 已取得 task ID 后超时，查询原 task ID。
- GPT 未取得 task ID 且提交结果未知时，不自动重试。
- 已完成单元不因其他单元重试而重新执行。
- 每次重试产生独立 attempt 记录。
- 超过重试上限后转人工处理。

### 11.5 断点恢复

以下状态必须持久化：

- 当前批次。
- 定制单元状态。
- 两道确认状态。
- recipe hash 和 compose hash。
- 外部 task ID。
- 本地 attempt ID 和提交结果未知状态。
- 执行步骤和尝试次数。
- 结果文件与文件哈希。
- 费用记录。

页面刷新、服务重启或回调延迟后，系统从持久化状态继续，不从头重复付费任务。

### 11.6 成本控制

- 批次执行前展示 GPT 单元数、Grounding 单元数和预计费用。
- 各服务费用分别统计。
- 每次尝试记录预计费用、实际 usage 和实际费用。
- 支持设置批次预算上限。
- 达到预算上限后停止创建新的付费任务。
- 已在运行的任务继续回收结果。
- 重试费用不能覆盖前一次费用。

### 11.7 批量操作

用户可以：

- 同步 WPS。
- 筛选无歧义单元。
- 批量确认方案。
- 批量开始制作素材图。
- 按路线、位置、状态和失败原因筛选。
- 批量重试选中失败项。
- 批量确认已查看素材图。
- 批量合成满足条件的效果图。
- 批量查看最终效果图。
- 导出已通过结果和失败清单。

## 17. 验收标准

### 17.1 WPS 与拆解

- WPS 原文和附件完整保存。
- 图号在同步、刷新和筛选后保持一致。
- 多位置、多视图和多版本能正确拆成定制单元。
- AI 结果不能覆盖或改写 WPS 原文。
- 关键歧义会阻塞对应单元。

### 17.2 路线

- “图1徽章＋普通红色弧形文字”进入确定性制作。
- “图1徽章＋文字，字体参考图2”进入 GPT Image 2。
- “图4的校徽”把图4作为内容素材，不触发 GPT Image 2。
- “排版按照图4”把图4作为参考素材并触发 GPT Image 2。
- 低清素材只能被修复或阻塞。
- 系统中不存在第三个顶层制作路线值。
- MediaKit 与文字渲染组合仍记录为确定性制作。

### 17.3 位置

- 2208 正面、背面和袖部标准位置能稳定显示占位框。
- 同一模板在不同屏幕尺寸下换算一致。
- 服装文件哈希变化后模板失效。
- 标准位置不产生模型费用。
- 非标准位置启用 Grounding 时，建议框必须经人工确认。
- 未启用 Grounding 时，不要求该服务通过生产验收。

### 17.4 GPT Image 2

- 使用真实 EvoLink Key 完成 1K、Low、transparent、n=1 调用。
- API 参数和提示词均明确要求透明背景 PNG。
- 页面明确显示透明 PNG 要求。
- task ID、查询或回调、usage 和费用完整保存。
- 创建请求超时且没有 task ID 时不会自动重复提交。
- 结果及时持久化并通过字节读回验证。
- 非 PNG、无 alpha 或透明区域无效的结果被拒绝。
- 透明验收失败不会静默转为 MediaKit 去底成功。
- 人工确认前不能进入服装合成。

### 17.5 批量

- 一个批次可以同时包含两条路线的多个单元。
- 单元失败不会阻塞其他源记录和版本。
- 只重试失败项。
- 页面刷新和服务重启后可以继续。
- 未知状态付费任务先查询，避免重复提交。
- 输入变化后相关确认失效。
- 较早配方结果不能覆盖当前结果。
- 达到预算上限后不再创建新付费任务。

### 17.6 合成与导出

- 只有素材图已确认的单元可以参与合成。
- 同一效果图版本的必需单元全部满足后才生成一张完整效果图。
- 同一件衣服的正面、背面和袖部必须在同一客户交付画布中展示，不能按位置拆成多张一面空白的效果图。
- 同一 WPS 中的不同服装方案或不同版本分别生成效果图，不能相互合并。
- 合成过程不调用生成模型。
- 素材位置与已确认占位框一致。
- ZIP 文件和映射清单一一对应。

### 17.7 验收层级

以下结果必须分开报告：

1. 本地类型检查、单元测试和构建。
2. 真实 WPS 同步。
3. 真实 MediaKit 调用。
4. 条件启用时的真实 Grounding 调用。
5. 真实 EvoLink GPT Image 2 调用、透明 PNG、任务回收和费用记录。
6. 批量幂等、恢复和失败隔离。
7. 人工视觉确认。

任一层通过不能替代其他层。
