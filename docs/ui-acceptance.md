# WPS 生产台发布与界面验收

每次改动先列明受影响流程与测试预期，完成代码检查并提交上线，等待 Vercel READY，再用 Computer Use 操作正式页面。发现本次改动导致的使用缺陷后修复、重新发布，并重测失败项与受影响项。

| 测试块 | 操作与通过条件 |
| --- | --- |
| 数据库与加载 | 首次打开、连续同步、并发预览、刷新恢复均能完成；记录耗时、超时次数和数据库等待类型；单张预览仅读取本版本数据，无新任务的同步仅读取任务顺序；读取失败不能显示为数据丢失或同步成功 |
| 制作按钮 | 首次制作、重做、继续处理立即有反馈；等待时同一图案不能重复提交；后台接收后显示排队或处理状态 |
| 失败反馈 | 超时、断线、服务拒绝分别说明原因、结果是否已保存与下一步；提交结果未知时先查询原任务，不能自动重复生图；旧失败提示不能遮住新提交进度 |
| 任务隔离 | 操作一行时另一行仍可查看与操作；失败保留旧图和候选；仅锁定本次图案及其共用范围；确认与定稿状态不被无关操作改写 |
| 页面回归与恢复 | 素材和候选大图、修改要求弹窗、位置调整、客户预览可打开和关闭；取消编辑不保存；刷新后已保存内容和后台状态一致 |

按修改范围追加测试：共用图稿关联与脱离、批量制作、款式颜色切换、上传、导出与客户定稿。没有涉及的付费或客户写入流程，不因日常验收自动执行。

记录每项的环境、操作、实际结果和必要截图。隔离环境中的模拟超时或断线只证明交互与请求保护；正式域名回读和真实页面操作单独记录，不能合并宣称真实供应商生成成功。真实付费模型验收使用明确的测试对象与费用范围。

发布完成需要：精确提交、Vercel READY、正式域名/API回读、Computer Use 界面结果。工具连接失败或项目既有缺陷分别记为未完成或已知问题，不能写成通过。

数据库相关变更额外验证：正式站逐项读取后进行一轮有限并发读取，对比错误率与耗时；用隔离数据库验证保存冲突、状态隔离与重连。测试中出现超时必须记录失败项，不用单次成功代替整轮结果。

本轮固定回归边界：普通原图保真、参考图只作样式、图文组合内部删除后加字、删除或去旧字核对失败、同稿多衣色应用部分成功、已定稿保留、保存回包丢失后读取核实、旧图与新失败并存、款式缺失。先验证本地是否已有等价修改，发布仅包含已核实的补丁；不批量重做历史图案或跳过内容核对。

自动共用回归：007 八色双位置应显示两份“8 处自动共用”且保留八个客户图版本，无“先核对并合并”步骤；刷新后组标识与 revision 稳定。隔离界面验证手动拆出、再刷新仍独立、制作一次应用多衣色；自动分组不确认图案、不生成客户图、不触发生图费用。不同要求/版本/素材、已有稿、定稿和后台候选不误并。网页与 worker 都发布后再验旧记录自动整理。
