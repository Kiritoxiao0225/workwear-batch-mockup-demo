# 工作服批量效果图 Demo Logic Map

## 当前增量：最终图案逐项核对（2026-09-11）

- `PAGE-007` / `API-007 reviewArtwork`：核对表绑定最终 PNG SHA、可见图层参数、文字及原图要求、服装位置。明确差异显示待修正；不确定、服务失败显示待人工核查；保存、编辑、上衣、下载与现有确认流程继续可用，不恢复评分门槛。
- `FLOW-009`：后台制作在最终排版后核对未覆盖的内容项目；相同最终图片已有核对则复用，步骤持久化。检查失败保留图片及待核查状态，不自动循环生图。纯文字无原图时转人工核查。
- `RULE-ARTWORK-REVIEW-VERSION`：已知图层改色只使颜色待核查；换字、排版改变更新相关项目；更换扁平图片使内容待核查。移动衣服位置仅更新尺寸与位置；沿用原上衣位置确认按钮时，同步记录这两项的人工核对，不增加重复确认。页面读取、刷新、移动均不发起模型核对。重新核对由新制作或明确点击触发，已完成项目复用。
- `STORE-005`：`artwork.validation.review` 保存各项状态、证据、要求和历史；人工核对符合或接受差异必须有说明，登录账号由服务端记录，本地模式明确填写操作人。元数据保存不改变图案、上衣位置、确认或客户图。最终检查基于原始素材角色及完整要求，旧中间步骤检查不冒充最终图通过。
- `UI-ARTWORK-CORRECTION`：新记录从当前未解决项目生成修正项，携带具体部位、实际、预期、改法与保留内容；已接受差异不再出现在待修正入口。旧未定稿任务可主动接入，不批量回写；已定稿记录只读且不重新计算结论。
- `TEST-ARTWORK-REVIEW-VERSION`：覆盖颜色/位置/换字失效范围、原图角色、最终 SHA、模型不可用后保存、手工决定审计、旧记录读取无变化及未解决项目不阻断原确认流程。发布状态以本轮验收回执为准。


## 2026-09-11 正反面一次确认

- `PAGE-009` / `FLOW-011` / `API-009`：双面校准弹窗统一勾选并“确认正反面位置”，草稿也一起保存；切换编辑面不改变提交范围，任意面调整撤销整次核对。单面底图保持单面按钮。
- `RULE-011`：一个事务核验全部视图的底图身份、权限、revision 与坐标，再写历史和审计；任一面冲突、缺失、不合法或写入失败时全部回滚。旧单面 API 继续兼容，批量保存不跨色、不覆盖新版本。
- `TEST-010`：隔离 PostgreSQL 覆盖双面草稿/确认、背面冲突、第二面写入失败、并发提交和单面素材；界面验证一次勾选、切换面保留核对、修改后撤销核对及刷新恢复。

## 2026-09-11 图文组合按可见边缘排版

- `FLOW-009` / `API-006` → 后台图案排版：自动组合在测量前读取图片实际非透明边界，以 `sourceBounds` 保存可见图层范围，原图片和颜色不变；透明留白不计入图文间距。特殊字体保留客户要求的组合方向，按组件实际宽高连续排列，不再等分画布中心。
- `RULE-010`：普通文字继续按印花尺寸测量；特殊字形独立保存，紧凑排版但不冒充逐字字高验收。自定义人工版式、整张品牌图、隐藏图层及已确认历史稿不自动重排；旧稿只在明确指定范围内修复。
- `TEST-008`：带大量透明留白的真实形状、普通文字实际间距、特殊字体四向排列、重复排版不漂移、自定义版式不变；最终 PNG 与上衣预览需人工查看。

## 2026-09-11 已有任务采用补充的衣身宽度校准

- `PAGE-009` / `API-009` → `PAGE-007` / `API-007`：缺少衣身宽度、尚未确认位置或成品的任务，在读取状态、预览和保存位置时读取同一款色、底图版本、图片 SHA、像素尺寸及单面 crop 的已确认腋点。只补尺寸依据，不替换任务绑定的位置标准或人工中心、旋转、图案；草稿与其他底图不得采用。
- `RULE-011`：补充基准记录 `bodyScale.standardId`，保存位置后固定到该确认版本，后续核验读取该历史记录；已确认位置/客户图和已有可用基准不随素材校准自动变化。保留现有 55 cm 参考衣宽规则，不写入实测衣宽。
- `UI-012`：补充校准改变时重新请求预览，不改变生产 revision；缺少基准返回 422 和素材库校准入口。位置保存携带画布使用的校准标识，变化时返回冲突，避免确认未看过的尺寸。
- `TEST-010` / `TEST-008`：覆盖未保存/草稿→确认→旧任务恢复、逐面隔离、继承坐标、换图与 SHA/crop 不符拒绝、历史确认固定、人工位置与成品保留、预览重读及保存时校准变更冲突；真实隔离 PostgreSQL 验证查询和保存衔接。

## 2026-09-11 图案制作规范 v4（当前规则）

以下规则替代本文历史记录中 80 分、1.25 倍、低分自动重绘及内容核对失败阻断的描述；历史回执仍保留原结论。

- `RULE-ARTWORK-ROUTING-V1` / `API-006`：正常制作仅在本地读取原生有效主体像素，不调用数字画质评分。尺寸明确时按指定宽/高及 `ARTWORK_REFERENCE_PPI`（默认 300，内部参考）计算目标；未明确尺寸时参考主体长边 1000px。空白和无关载体不算主体像素，目标不是确认门槛。
- `FLOW-ARTWORK-ENHANCEMENT`：像素不足或真实识别到模糊、压缩损伤时自动保真增强一次；不因旧评分低或评分失败重绘。生成结果若像素不足，也只做一次保真增强，记录实际尺寸，仍不足提示人工核查。实拍目标先定位再重建；显式选择重建按客户要求执行，不以评分为前提。保留原比例、前景颜色和透明保护，增强失真不会冒充成功。
- `FLOW-ARTWORK-SOURCE`：使用保存的原始素材，先定位完整目标区域，再记录逐字顺序、位置、确定/不确定内容、结构、颜色、排版及具体问题。弧形文字沿弧线逐字识别，不跳字补猜。初次不完整且有区域时最多追加一次原像素裁剪核查。客户明确文字优先于可辨原内容，不确定内容只作为疑点，不作为确定提示词。
- `RULE-ARTWORK-CONTENT-REVIEW`：完整可用图片的整图、删内部元素、去旧字和特殊字体核对统一为提醒。failed 保留实际差异；uncertain 显示“可能会不一致，请人工核查”；服务或回执异常显示“自动核对未完成，请人工核查”。继续编辑、保存、上衣、预览和人工确认，不自动代替客户确认。文件缺失、下载不完整、损坏、空白或未完成的组件仍是实际制作失败。
- `UI-ARTWORK-CORRECTION` / `API-007 jobs`：按本次服务端核对记录列出部位、当前情况、预期、修正动作和保留范围，去重后让用户勾选“按这些问题修正”。一次提交生成一张修正版，原图、当前版本、已选问题和输入角色一并传入；不复制样式参考图内容，不自动循环修正。API 校验 runId、选项和原图快照；同一修正输入防重，保留旧版本与新版本回执。
- `FLOW-ARTWORK-DOWNLOAD` / `STORE-ARTWORK-JOBS`：增强回执（task_id、结果地址、过期时间）先保存，再下载。下载单独持久化，最多 3 次 GET/读体，校验完整像素后才保存文件；只重试下载，不重复生成/增强。地址失效明确提示恢复原服务任务，不能自动另付费生成。未知增强提交与未知生图同样锁定，跨 worker 接管也不能再次提交。
- `PAGE-007`：进度写入后台任务，切页刷新恢复；展示实际像素与增强步骤，移除主流程评分按钮和数字评分门槛。保存、内容提醒、上衣和客户定稿为独立事实，单图加载失败只重读该图。
- `TEST-ARTWORK-ROUTING-V1`：路由、像素、管线测试覆盖零评分、低清一次增强、组件核对 failed/uncertain/服务故障后继续、坏图拒绝、明确重建、源区域与文字角色；下载测试覆盖截断/断线/失效及最多 3 次 GET；修正测试覆盖具体问题/去重/参考角色。队列集成测试另验增强未知提交、防重、接管和已完成步骤复用。发布与真实素材结果以本轮回执为准。


## 2026-09-11 制作保存与提交超时修复

- 自动发现复用本轮生产快照，已解析且原文/素材未变的订单不再逐条进入队列事务。解析入队与共用图稿入队均在事务外读取完整状态，短事务只锁定 revision 并核对版本；并发修改会重新读取，保持原有快照、共用关系和付费去重约束。
- 制作提交回包丢失后按单元保存待核实状态，阻止同范围重复提交并提供只读查询。新/更新的后台回执会清除提交超时提示，旧失败回执不能冒充本次结果；实际制作失败仍显示后台原因和保留图片。
- 验证包括 `production-enqueue.test.ts`、`artwork-jobs-response.test.ts` 和 `production-reliability-integration.ts` 中持有真实生产行锁时的无变化发现检查；发布及真实任务恢复以当次回执为准。

## 2026-09-10 线上问题根因修复边界

- PAGE-007 / API-007：全量生产状态每次读取仍用同一条数据库查询核实 revision 和 updated_at，仅在两者未变时复用进程内快照，返回独立副本；数据库超时或状态缺失继续报错。CAS、文件引用保护、客户版本隔离及确认条件不变。首次读取和真实修改后的全量传输仍需完成，不以缓存掩盖数据库故障。
- API-006 / C 图文组合：明确要求删除主体内部元素时，先对当前可用主体局部删除，再逐条核对删除范围、其他图形文字配色和数量，核对通过后继续原文字排版。删除失败、结果不明或回执不对应当前图片时保留组件，不保存成品、不自动再生图。普通去背景、去旧字、参考图及严格禁止模型改图各沿用原合同；不自动改写历史产物。
- PAGE-007：共用稿保存、逐位置应用、人工图案确认、位置确认分别显示；新制作失败仍展示旧稿保留说明。缺款式显示实际匹配原因；统计明确位置数、图稿数和费用口径，不改变业务状态和预算规则。
- 回归证据：production-cloud-state.test、production-storage-integration（真实隔离 PostgreSQL）、artwork-model-edits.test、artwork-standard-pipeline.test、shared-artwork-status.test、shared-artwork-integration、artwork-jobs-integration；界面按 docs/ui-acceptance.md 用 Computer Use 验收。

### `FLOW-011` 素材导入、换版与位置标准沉淀

- 清单盘点 → 逐文件哈希核对 → 登记待上传 → 上传并读回 → 原图候选/规范底图/缩略图关联 → 款式与颜色款 → 底图版本 → 正面/背面视图 → 人工标定 → 保存草稿或明确确认。
- 整批入口：`scripts/catalog.ts`。261 个成品文件按已确认的规范布局识别，款号按源目录最长前缀匹配，保留原颜色名。多款号图隔离，0 字节源图单列，不中断其他记录。源文件角色仍是名称匹配候选，未伪造逐面确认。
- 上传入口：`POST /api/catalog/upload`，支持 png/jpeg/webp、最大 64 MiB；必须明确声明单面或左正右反的等半幅布局。换版要求提交当前 asset version ID，新底图从未校准状态开始；同内容重传复用，历史清单重跑不回退当前底图。
- 2026-09-08 衣身比例预计算：`importCatalogAsset` 在发布当前底图版本前复用已上传的原图字节，核对 SHA/像素尺寸并计算各面衣身宽度占比，保存到 `catalog_body_geometry`。派生键绑定图片 SHA、尺寸、面裁切与算法 `alpha-torso-v1`；已确认腋点标准仍优先，55 cm 仍是效果图换算基准，不改为实测衣宽。无可靠轮廓时保存空结果，允许入库并继续人工校准，不反复读图猜算。旧资产由 `scripts/prepare-catalog-geometry.ts` 每批最多 3 项补齐，覆盖历史版本；读取遇到缺失派生值兼容补算。备份/恢复包含派生表，不能替代人工标准或客户任务快照。
- 同款复用：选择代表颜色 → 人工确认需要的面 → 读取各色真实图片、校验文件 hash → 按透明轮廓计算对齐及套用预览 → 用户核对所选颜色的领口/门襟/口袋和位置 → 同一事务保存来源版本引用及对齐参数。已有草稿或标准的目标面保留，不批量覆盖。新增颜色使用稳定 style ID 沿用款式身份，无需重导整款。

### `API-009` 商品素材库接口

- `GET/POST/PATCH/DELETE /api/catalog/session`：读取、登录、续期、注销；POST 仅接受密码，由服务端 `CATALOG_LOGIN_EMAIL` 绑定现有账号，缺配置时拒绝登录；不扫描用户匹配密码。用户通过 CLI 初始化（密码 8–256 位），无公开注册；原身份、角色及禁用规则保留。登录连续失败会限时锁定该账号。登录与续期同时设置数据库到期时间及 30 天 HttpOnly / SameSite=Lax cookie（生产环境 Secure，路径仍为 `/api/catalog`），响应不缓存。PATCH 校验 Origin，只能续期未过期且账号未禁用的既有会话；过期、注销和禁用均不能自动复活。
- 加载优化：普通打开沿用列表已有整款颜色，保存/上传后仍重新读款式；详情的 provenance/current asset 由首次关联查询取出，减少两次数据库请求。每次重新读取标准与 revision；服务实例仅缓存与 asset version、thumbnail file ID 和 face crops 绑定的轮廓边界（最多 256 项，并发合并，失败不缓存），不缓存可变标准或图片字节；冷实例需重新计算。画布先显示缩略图，高清底图随后覆盖。
- `GET /api/catalog/products/:id?placementPreview=1`：只读生成位置建议；返回与底图版本绑定的 placementPreview。未保存面有可靠透明轮廓时按各自缩略图设置衣服边界，并根据本批 21 款已看图核对的参考类型提供可修改标记；外部命名空间/未知款号需先选择类型，不推断为已知款。已有草稿、已确认与继承标准原样保留。无可用透明轮廓时返回空标记，不再按整幅照片猜测印花/禁区；弹窗先引导拖框选择衣服布面，再显式生成参考位置。只有正面时放大该面，不用一半区域展示不存在的背面；结构与禁区仍是待核对参考，不宣称 AI 检测完成。
- `GET /api/catalog/products`：搜索、筛选、分页和导入异常；`GET /api/catalog/products/:id?assetVersionId=...`：当前或历史底图详情、来源候选与标准版本。
- `GET /api/catalog/products/:id/framed-preview?assetVersionId=...`：需项目登录，只读生成绑定指定底图版本的带框 PNG；返回 inline、private/no-store，失败可在大图弹窗重试。`lib/server/confirmation-frame.ts` 使用固定白色安全区域确定性排版，不调用模型、不写生产记录。
- `GET /api/catalog/styles`：按款式搜索、分页及颜色聚合；`GET /api/catalog/styles/:id`：整款颜色与代表颜色。当前素材库使用此聚合接口。
- 2026-09-08 待领取与首屏性能修复：`GET /api/wps-tasks` 只返回设计中和待领取任务（2026-09-09 扩大同步范围）；先按 AirScript 增量清单里的真实状态筛选 ID，再读取这些记录的完整附件地址，不下载/上传图片字节。开始分析和整理提示词时只重新核验目标记录并保存所需附件；导出只核验本站已存记录。记录缓存最多复用 5 分钟以刷新过期签名，证据比较忽略 WPS 地址的认证签名参数，但仍检查附件 ID、路径与其他图片参数。无需更新客户原表脚本。
- 素材库首屏：列表鉴权后一次查询并签发本页默认卡片的缩略图链接，浏览器直接读 OSS；原 `thumbnailUrl` 文件 ID 不变，短时链接过期时经原鉴权接口重新取得地址。其他颜色和高清图保留原入口。
- Vercel 连接池：同一进程的路由模块通过 `globalThis` 共用最多 5 条连接；驱动 5 秒回收空闲连接，查询/事务结束后 `after()` 合并回收任务，连续空闲 6 秒且没有活跃操作时先解绑旧池再关闭，迟到回调不触碰新池。仅 Vercel 连接设置数据库侧 `idle_session_timeout=60s`，实例暂停后也能清理事务外空闲连接；运行中事务不受该超时影响。2026-09-10 应用账号 `mockup_app` 的连接额度提升到 100，整库 `max_connections=100` 和管理员预留 3 条保持不变，实际可用数量仍受整库及其他服务占用限制。部署区域 `sin1`；身份、事务及文件引用保护规则不变。
- 生产台效果图预览共享页面级下载队列，最多同时下载 3 张，直到响应体读取完成才释放名额；取消的排队预览不发请求，失败不自动重试。需求解析继续最多 5 条并行，保存逐条提交。
- 2026-09-08 查询优化：素材库款式列表合并统计、当前页款式与导入异常为一次元数据查询，再读取该页整款颜色，共两次数据库往返；保留状态筛选、颜色命中和整款颜色展示。生产台款式选择直接一次读取全部当前款式与颜色，不逐页重复查询统计和导入异常；未缓存可变标准。
- `POST /api/catalog/reuse`：建立真实对齐预览和服务端检查记录；`PUT /api/catalog/reuse`：提交检查 ID 和人工复核声明，批量保存引用。客户端不能提交自己的分数或对齐结果。
- `GET /api/catalog/files/:id`：校验会话后，OSS 文件跳转短时签名 URL；本地验收文件校验 hash 后返回。只接受数据库 file ID。
- 2026-09-10 OSS 端点统一管理：`lib/server/catalog-oss.ts` 是 SDK 唯一创建入口。所有服务端对象读写、上传前检查、读回校验和旧图删除/HEAD 默认加速，`readCatalogFile` / `saveCatalogFile` 不再接受业务层加速开关，因此衣身补算、位置预览、商品上传、带框预览、围裙识别、颜色复用和模型原图留档自动覆盖。文件保留目录仍由 `purpose` 决定；Bucket/前缀、SHA、版本号、私有上传及防覆盖保护不变。浏览器原图/缩略图签名继续使用区域端点；Bucket 版本状态查询通过独立区域管理入口，删除与管理继续使用现有目录限定删除账号。接口类型隔离对象操作、签名和 Bucket 管理；ESLint 禁止业务模块和脚本直接导入 `ali-oss`，防止新增入口绕开策略。不改 WPS/模型服务商自己的地址或 Bucket 设置。回归覆盖默认读写、签名例外、旧图删除回读/失败留队及存储归属保护；本地验证与正式发布分别记录。
- `POST /api/catalog/standards`：素材库一次提交当前底图全部面的草稿或人工确认，`views` 包含每面的坐标与 revision；先逐面校验再在一个事务中写入，任一面不完整、冲突或写入失败时全部回滚。单面素材提交唯一面；旧单面请求合同仍兼容。校验登录角色、Origin、结构化坐标、当前底图和视图 revision。
- Errors: 未登录 401、无权限/来源不匹配 403、不存在 404、底图或 revision 冲突 409；缺配置明确报错，不回退静态商品或本地文件。

### `RULE-011` 图片身份、标准版本与权限

- 稳定 UUID 关联款式/颜色/图片，文件名不作主键；不同来源的相似款号不自动合并。
- 正反面画布 crop 与衣服局部 frame 分开；结构点、锚点、可印区、默认尺寸和禁区均属于当前面局部坐标。不存在的面不能建立标准，帽子/马甲不得使用袖部位置。
- 无轮廓照片首次打开没有自动结构点、印花或禁区；先手动框选衣服区域（至少各占画布 2%），再生成并调整参考标记。已有草稿与已确认标准始终保留，不自动改写；手动框选与生成不会直接保存或确认。
- 位置建议仅存在于当前预览，打开页面不写标准、不确认、不触发 AI 或复用。一次勾选已核对全部现有面后确认；调整任意面会撤销本次核对状态。保存与确认将当前底图各面的编辑一起提交，全部成功后刷新，失败保留编辑；单面素材只提交现有面。换结构/重新生成只在用户明确操作后替换当前编辑，历史版本保留。
- 只在同一稳定 style ID 内复用同面、同布局。来源必须是当前底图的最新人工确认版本，不允许继承链；继承不计为新的人工真值。
- 对齐算法 `alpha-bounds-v1`：在每面 320×384 采样透明轮廓，边界归一化到 160×192 比较；重合度至少 97% 且衣服宽高比变化不超过 3% 时预选。无可用透明轮廓或有差异时不预选，必须人工看预览决定；坐标越界则禁止复用。该判断只辅助复核，绝不宣称已检测内部结构。
- 检查记录绑定来源标准、目标底图视图与 revision、操作人和算法版本，有效期 24 小时。提交时再次验证当前来源/目标，任一陈旧则整批回滚；相同检查 ID 重试幂等。来源后来改变时，已有继承仍引用旧确认版本；目标换图后不带入旧标准。已有独立草稿或标准不覆盖。
- 确认要求结构类型、必要结构点、至少一个允许位置、范围内锚点/默认尺寸，以及可印区不与禁区重叠。数据库事务锁定该视图及颜色款，按 revision 拒绝陈旧修改；旧底图不允许继续保存标准。
- `components/project-session.tsx` 在应用布局共享项目登录：首次打开、页面回到前台、网络恢复及可见页面每小时尝试续期；后台标签页不定时续期。首次登录或有效会话恢复后，生产表自动读取真实款色，不再另开素材库页面登录；两页共用同一个登录弹窗和顶部退出入口。连续约 30 天未使用、主动退出、清除 cookie 或账号禁用后需重新登录；不同浏览器与不同域名需要各自首次登录。密码不写入浏览器持久存储，刷新或 Web 实例重启依赖 PostgreSQL sessions 和 cookie 恢复。
- 登录用户决定操作人；viewer 仅能查看。当前认证范围只包括新增素材库 API，WPS 与原 Demo 存储迁移另属后续阶段。

#### 素材分流、抠图门禁与主体换色 V7（正式业务代码已实现）

- Source classifier: `inspectArtworkSource` 不再用“全图出现 2% 透明像素”直接放行；已有透明素材必须同时满足有效主体、硬 Alpha 与边缘透明占比，防止带透明圆角/细边但仍含底色的 PNG 绕过处理。无可靠透明通道时，以边缘主色占比和边缘纹理密度区分 `flat-background`、`uncertain-background`、`complex-background`
- Independent preflight: `textMode`只表示是否保留参考图内文字，不再推导 `sourceScope=wholeImage`。缺省 `sourceScope=subject`；只有客户明确要求“整张/整图/原样/保留背景/完整图案”时才允许 `wholeImage`，否则 API fail fast
- Quality gate: 背景分类与清晰度分开判断；纯色底先用边缘连通法估算实际主体框，透明图用 Alpha 主体框，再用完整图案图形目标长边 1000px 计算放大倍数。`≤1.25×` 为 `usable`，`1.25–4×` 为 `low`，`>4×` 为 `severe`；同时结合 MediaKit `blur`/`vqscore`/噪声/压缩痕迹，最终等级取最差项
- Flat/transparent route: `flat-background` 和有效 `transparent` 素材先锁定全部前景 Alpha，再按前景外接框加 4% 安全边距裁剪；纯色或低纹理平滑渐变底的小型字标都走该路线。Professional 门禁与画质评估使用裁后输入，不再用大面积空白/纯色画布尺寸。裁后短边不足 256px 只补透明/底色边距，长边超过 2048px 等比缩小；短边不足 128px 的细字图形在复用蒙版时加固软 Alpha 笔画。达标时保留原像素；低清 Logo、校徽、商标或带字图形只使用 Professional `fidelity_first` 2×，不用 Standard 重构品牌图形。增强只更新 RGB，完成后复用锁定蒙版、移除极小孤立噪点并消除底色污染；若增强导致长宽比变化超过 1% 则 fail fast
- Complex route: `uncertain-background` 与 `complex-background` 先评估画质，再选择不增强、Standard 2× 或 Professional `fidelity_first`，最后调用 `remove-image-background(scene=product)`。Standard 超限输入按短边≤1440、长边≤2160 等比缩放，1280×2272 必须得到 1217×2160，禁止横竖颠倒或压成 811×1440
- Cutout gate: 云端和本地透明结果在写入草稿前检查可见主体面积、全透明背景占比、画布边缘透明占比、完全不透明主体占比与半透明像素占比；失败即停止，不静默使用模糊或近乎整张不透明的结果
- Recolor mask: 图形原图与换色蒙版分开保存；预览和 Canvas 导出按蒙版逐像素替换 RGB，并保留或补足原 Alpha，不再用半透明颜色叠加，避免抗锯齿边线残留原色。针对“手势主体”等具体对象，先用主体主色与面积锁定主要组件，再吸收主体附近的非白色轮廓线，并重建被同色背景去底误删的狭窄内部线槽，因此填充和边线一起换色；与主体分离的小音符和主体内部白色细节仍保持原色。旧草稿没有蒙版时保持原色并禁用整图覆盖式换色
- Honest boundary: 结构相似度、轮廓完整性与品牌图形语义仍需人工看图确认；当前门禁只保证 Alpha 与局部换色结构合理，不能把自动质检描述为品牌 Logo 的最终相似度证明

#### 完整制作图案处理路线 V9（正式业务代码已实现）

- Route first: `API-006` 在调用 MediaKit 或 Seedream 前先完成一次确定性路由；输入同时携带主要素材的稳定图号、最多一张额外参考图和 `processingRoute=auto|fidelity|hybrid|model`。自动判断只读取制作意图、主体有效像素、目标放大倍数和参考图关系，不再用“背景复杂”决定是否进入大模型
- Component plan: 每次处理先生成组件配方，明确主要图形是否进入成品、每段文字采用程序文字还是模型特殊字形、每张参考图是否仅作字体/风格/排版参考，以及最终图层顺序。自动命中整体构图参考时，路线选择仍保持“自动判断”，旁边独立显示“预计：模型一体生成”；行内输入卡同时展示必须进入成品的内容源缩略图、仅作风格/排版参考的缩略图、准确文字骨架和同批次提交的完整制作要求，不再用旧的分层拼接卡表达模型一体生成
- Fidelity route: 主体清晰且需求只是去背景、保留/换色、普通准确文字和常规排版时走 `fidelity`；该路线继续本地确定性去底或 MediaKit 画质评估/保真增强/商品抠图，并建立可分离的 Logo 图形层与准确文字层
- Hybrid route: 成品同时需要保留 Logo/图形和参考样式的单个特殊文字，且参考图不决定完整图案的比例、层级或整体版式时走 `hybrid`。主要图形独立执行 `fidelity`；特殊文字按准确文本分段调用 Seedream 4.0，只允许生成该段文字；参考图只进入对应文字生成请求，不成为成品图层；最后由程序建立可独立编辑的图层
- Model route: 主体目标放大倍数 `>4×`、主体短边 `<128px`、需要从照片中选择性取材/重构、多素材重新组合，或参考图同时决定“图形＋文字”的整体版式、相对比例、位置关系或视觉层级时走 `model`。该路线把主要素材、参考图和完整要求一次交给模型，跳过 MediaKit 增强和抠图，直接生成不可分层的完整候选并继续人工验字/验图
- Canonical prompt: 模型一体生成只允许使用 `buildCanonicalArtworkModelPrompt` 产生的 `task-review-artwork-v2` 最终要求。表格里的“实际提交给 Seedream 的制作要求”、`API-006` 请求审计字段和 Ark 图片请求的 `body.prompt` 必须来自同一个纯函数；提示把 WPS 原文标记为唯一客户事实，把 unit instruction 标记为可修改的系统结构化解释，前者优先且后者不得补充原文未说明的颜色、大小、层级、对齐或构图要求。内容素材固定为模型输入图1，参考图随后按 WPS 图号排序；新增准确文字的限制不得删除内容素材自带的品牌/校徽文字。视觉理解模型只负责确认可生成与歧义，不得重写最终生图要求
- Prompt consistency gate: 浏览器提交 `expectedPromptVersion` 和 `expectedPromptHash`；服务端根据收到的结构化字段重新生成最终要求并在任何付费图片调用前逐项核对。版本或 hash 不一致时 fail fast，既不调用 Seedream，也不接受页面展示与真实请求不一致的结果；生成草稿同时保存最终 prompt、版本、hash 和图片映射，供人工审计
- Manual override: 表格结构不变，每个图案子行顶部提供紧凑四态选择；用户可强制自动判断、原图保真、混合处理或模型生成。切换路线会使已有候选进入 `needsRegeneration`，并纳入 `artworkRecipeFingerprint`，旧异步响应不得覆盖新路线
- Reference mapping: 理解模型按 WPS 原始素材顺序保留 `图N` 语义，再映射为 Logo Studio 连续输入；当前合同最多接收主要素材加一张参考图，超过上限时 fail fast。`A+图N+B【参考图M】` 由确定性规则规范为“文字 A → 图N主体 → 文字 B”，图M只作字形/风格/排版参考且不得进入成品；未在该单元 instruction/layoutNote 中明确出现的模型臆造参考图会被移除。只用于排版/位置判断的参考图仅进入理解模型，不送进 Seedream，避免人物、衣服和场景污染完整图案；字体、笔触、颜色或风格参考才同时进入对应特殊文字的生图请求。进入 Seedream 前还会从原始要求中删除衣服款式与左胸/后背等落位词，生图提示固定为独立二维平面素材并禁止人物、衣服和场景
- Honest boundary: 混合路线中的特殊文字仍是模型候选，可能错字或笔画偏差，必须逐层人工核对；模型路线则是不可分层的完整候选。真实“研 + 图5 + 2026，参考图4”现在因图4同时决定字形、整体层级和排版而走 `model`：图5是必须进入成品的主体，图4只参考整体视觉关系，两张图与完整要求一次进入 Seedream；候选仍不因接口成功自动确认。区域 OCR、品牌结构相似度和模型结果自动回退仍未接入

#### 表格行内图案处理 V9（正式业务代码已实现）

- Structure: 继续保留 V4 的三列父记录分组表和 5 个 WPS 父任务；9 个完整制作图案仍是中列独立子行，不新增页面、不拆散父记录，也不把同一 WPS 行复制成多行
- Inline controls: 每个图案子行直接展示路线、主要素材、素材范围、准确文字、制作要求、参考关系、衣服款式和制作位置；用户可在当前上下文完成修改、处理或上传成品，无需先打开生成前弹窗
- Result boundary: 未生成时显示制作配方和真实来源缩略图；生成后显示完整图案结果。只有点击生成结果或“调整图案”才打开 `TaskReviewArtworkEditor` 大画布，用于 Logo 换色、文字、变形、排版、位置和吸附基准线精修
- State safety: 修改路线、素材、范围、准确文字或要求会撤销确认并标记 `needsRegeneration`；旧候选保留为“上一版完整图案”供比较，但不能再次确认。处理请求继续使用配方指纹，避免旧异步响应覆盖新要求
- Preview rule: WPS 素材和子行来源图点击均只打开高清预览；选择框才改变主要素材。保存精修仍不等于确认，批量任务只收集显式确认的图案

#### 原始证据重置与重新理解 V10（正式业务代码已实现）

- Evidence-only snapshot: `lib/task-review-snapshot.ts` 只保存 WPS 原字段和 11 张原始图片路径；素材描述也只保留稳定图号，不再硬编码图片角色。旧的 summary、9 个 generation unit、instruction、exactText、layoutNote、候选图和确认状态均不属于生产快照
- Derived-state boundary: 需要固定派生状态的单元测试使用 `lib/testing/task-review-fixture.ts`；生产 API 和页面禁止读取该 fixture。`GET /api/wps-tasks` 在本地测试模式返回 `reviews=null`，因此页面与实时 WPS 一样必须调用 `API-005` 从原始证据重新理解
- Local image delivery: `API-005` 遇到 `/task-review-originals/...` 本地路径时，在服务端校验路径、格式和 8MB 上限后读取为图片 Data URL，再提交给视觉理解模型；不再把 Ark 无法访问的相对 URL 当作图片输入
- Interpretation contract: 模型可以拆分衣服、位置、版本、图号关系和准确文字，但不得把原文未说明的字号、比例、间距、对齐、颜色、层级或视觉风格写成客户要求；未知项必须留空或进入 ambiguities。固定简写 `A+图N+B【参考图M】` 只保留原文明示的组件顺序和参考关系，不再自动添加“主体居中”“最大主视觉”“深色单色”或“不得机械横排”等设计判断
- Regeneration rule: 页面加载先按当前 WPS 原文、素材标识和分析版本恢复逐条缓存，仅对未命中记录调用模型；“重新分析全部任务”绕过缓存并用逐条新结果替换对应派生 review，同时保留尚未返回行的现有表格，避免等待期间整页清空。任一行失败或 120 秒超时只标记该行，不撤销其他已返回结果。重新理解阶段只调用任务理解模型，不调用 Seedream 生图；每个图案仍需用户随后逐项处理和人工确认

### `API-ARTWORK-JOBS` 云端图案制作与阶段调度

- Entry: `PAGE-WPS-PRODUCTION` 每行制作按钮、当前筛选批量制作 → `POST /api/wps-production/jobs`；`GET` 读取后台心跳、队列、阶段耗时及已保存失败候选。开关 `ARTWORK_DURABLE_JOBS=1`，旧入口在开关关闭时保留。
- Flow: 提交单元与原始需求快照 → 数据库同位置防重 → worker 持久执行目标识别、按需保真增强/生图、抠图、内容提醒 → 排版与 PNG 验证 → CAS 保存 → 更新客户预览。正常制作不占用历史评分槽。

- Rules: 队列跨浏览器及后台实例共享；同单元在途任务唯一；只有未开始任务可取消。完成步骤按输入摘要复用，失败续做保留此前已生成 PNG。付费生图提交结果未知时停止并锁定原任务，禁止自动重生。单元或源材料快照变化时禁止覆盖；保存操作 ID 与后台任务 ID 相同，提交后中断可幂等回读。

### `STORE-CUTOUT-IMAGE-REFS` 抠图回执文件引用与短上传事务

- `ARTWORK_CUTOUT_FILE_STORAGE=oss` 时，抠图 `job_json` 内联图片按原始字节存入现有文件库，用 `$cutoutImage` 引用替代；读适配器兼容旧 Base64 与新引用，并恢复旧 API 的 Data URL，保留 jobKey、source/output SHA、provider taskId、pending/unknown 与明确失败重试规则。`artwork_cutout_files` 保留回执关联的全部图像，GC 和备份包含这些引用；不重新编码，也不重新抠图。
- `production:migrate-cutout` 默认只读统计，`--apply --limit=10` 小批迁移；只有 job_json 与读取时一致才更新，防止覆盖正在回来的供应商结果。混合格式可继续读取。完整恢复仍要求备份与目标迁移版本一致；旧备份先恢复到同版本再迁移。
- 文件上传用 `production_operations` 的 owner/租约登记，OSS GET/PUT/校验和本地文件写入在数据库事务外进行；最终短事务核对租约并原子写 ready 与文件引用。失效旧 owner 不能发布，同 SHA 并发复用现有内容，PUT 禁止覆盖并校验回读 SHA；GC 不删除 pending 上传文件。保留默认连接池大小。
- 滚动启用顺序：迁移 012 → 部署支持双读的新 Web 和 worker → 开启 `ARTWORK_CUTOUT_FILE_STORAGE=oss` 和 `WPS_DURABLE_ANALYSIS=1` → 分批迁移旧回执。暂停新解析可关闭开关并排空 worker；文件引用产生后回滚必须保留双读适配器。
