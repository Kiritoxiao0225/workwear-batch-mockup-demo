# 存储空间与删除 · 详细方案（2026-10-28）

## 0. 要达到的效果

1. 用户随时能看到自己用了多少空间，知道哪些东西占得多。
2. 用户能自己删除，删了马上退空间额度，R2 上的文件也会真的删掉。
3. 删除时可以选择保留解析记录，以后重新上传原图，就能接着用原来的解析出图。

## 2. 用量显示

**2.1 顶栏进度条**（电商主图、图稿生成页面都显示）
- 写成「已用 2.0 / 100 GB」。
- 用到 80% 变黄，提示「空间快满了」；95% 变红。
- 满了以后，上传和生成按钮直接灰掉，提示「空间已满，去清理」，点一下进入存储空间页。

**2.2 「存储空间」页**（放在「我的账号」下面）
- 最上面是总量条，下面分三块：电商主图、图稿生成、回收站，各自显示占了多少。
- 每个商品或每条图稿占一行：缩略图、名称、占用大小、**删掉能释放多少**、最后使用时间。默认按大小从大到小排，也能筛出「超过 30 天没用过的」。
- 「能释放多少」和「占用」可能不一样。同一张图被几个商品共用时，要等最后一个也删掉才真正释放，所以单独算一列，免得用户删完发现空间没变。
- 可以勾选多行，一次批量删除。

**2.3 管理后台**
- 每个账号的用量（现在已经有了）。
- 加一个「改额度」按钮，以后不用再手动改数据库。
- 显示每个账号回收站里有多少。

## 3. 三种删除

适用于电商主图的商品和图稿生成的记录。

| | 删掉什么 | 留下什么 | 之后还能做什么 |
|---|---|---|---|
| **只删原图** | 上传的原图 | 出好的图、解析、方案、文案 | 成品照样能看、能下载。要重新出图，得先重新上传原图 |
| **只删图片** | 原图、出好的图 | 解析、方案、文案、提示词、每张图的小缩略图 | 记录显示「图片已清理」。重新上传原图后，可以直接接着出图，不用再付解析费 |
| **彻底删除** | 全部 | 只留扣费流水（对账要用，用户看不到） | 找不回来 |

规则：
- 删除弹窗写清楚三件事：「会释放 X GB」「7 天内可以在回收站恢复」「已扣的积分不退」。
- 正在解析或出图的不能删（跟现在一样）。
- **小缩略图**（长边 400 像素，一张约 30 KB）留着有两个用处：记录还能认得出是哪一款；重新上传原图时，可以拿它来对编号。缩略图也算进用量，但不到原图的 1%。

## 4. 回收站和每天清理 R2

```
用户点删除
  → 从页面上消失，进回收站；额度马上退；文件标成「待删除」并记下时间
  → 7 天内：可以一键恢复（恢复时重新占额度；空间不够就提示先清理）
  → 用户也可以点「立即彻底删除」或「清空回收站」，不用等 7 天
每天台北时间凌晨 3 点批量清理
  → 找出放满 7 天的，加上用户点了立即删除的
  → 逐个检查：全库还有没有地方在用这个文件（所有账号、所有功能）
       还有地方在用 → 跳过，只解除这一处的使用，不删文件
       没有地方在用 → 标成「删除中」→ 从 R2 删掉 → 确认 R2 上已经没有这个文件 → 标成「已删」
  → 删失败的留到第二天继续删，直到删掉为止
  → 写一条日志：删了多少个文件、腾出多少 GB、失败几个
```

安全措施：
- **查有没有地方在用，要查全库。** 系统里同一张图只存一份，可能被几个商品、几个账号同时用。数据库里一共有十几处会用到文件，每一处都要查到。
- 标成「删除中」的文件不能再被新的记录使用。这个保护数据库里已经有了，沿用。
- 每天一次最多删 2000 个文件或 20 GB，超过就停下来报警，防止程序出错一次删掉一大片。
- 从 R2 删文件用单独的「只能删除」密钥（代码里已经预留了位置），不用平时读写的那把。
- **上线后第一周只出清单、不真删。** 每天把「本来要删哪些」记下来，你看过没问题，再开真删。

## 5. 保留解析后重新出图

**电商主图**
- 记录页显示「图片已清理」，列出原来每个编号（图1、图2……）的小缩略图。
- 点「重新上传原图」，上传后系统按相似度自动把新图对到原来的编号上，用户确认或手动调整。
- 编号都对上以后，就能直接出图、单张重画、再出一套，不再收解析费。
- 顺带解决一个老问题：现在 30 天自动清掉原图后，「再出一套」和单张重画都用不了，以后重新上传原图就能恢复。

**图稿生成**
- 保留 AI 整理出的 7 项内容和提示词。
- 重新上传参考图后，可以直接出图。

**不上传原图能不能重新出图？** 不能。AI 出图时要拿原图当参考，只有文字解析，画不出跟原商品一致的图。

## 6. 旧数据怎么处理（上线时一次性做）

- 以前删掉的图稿记录：补退额度，统一放进回收站，**从上线那天起算 7 天**，给用户留出反悔的时间。
- 以前删掉的主图商品，以及 30 天自动清掉的原图：额度早就退了，文件统一进入清理流程。
- 没有任何账号在用的 863 个文件，和 297 个上传失败留下的文件：同样进入清理流程，删之前照样查全库有没有地方在用。
- **第一次真删之前，把清单给你过目**：多少个文件、多少 GB、分别属于哪些账号。你确认后再删。

## 7. 分几步上线

每一步单独上线，上一步稳定了再做下一步。

1. 用量显示、存储空间页、后台改额度。只是显示，不删任何东西，风险最小。
2. 三种删除、回收站、恢复。图稿删除改成真正退额度。
3. 每天清理 R2：先空跑一周只出清单，你确认后再开真删。
4. 保留解析后重新上传原图、接着出图。
5. 旧数据一次性清理（等你确认清单）。

## 8. 做之前要先核实的

- **图稿的文件找不找得全。** 图稿的文件平铺在几个公共目录里（客户图、制作图、确认图），不是一条图稿一个目录，要读每条图稿的记录才知道它用了哪些文件。要先写一个盘点脚本，对 690407784 这类账号逐个对账，确认能找全了再开删除。找不全的文件宁可不删。
- 线上有没有配好「只能删除」的那把 R2 密钥。
- 数据库每天备份、只留 3 天，比回收站的 7 天短。所以文件真正删掉的时候，留着的备份里这条记录都已经在回收站里了，用备份恢复数据库也不会出现「记录正常、图却没了」的情况。
