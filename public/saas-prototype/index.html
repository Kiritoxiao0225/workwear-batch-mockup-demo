前端原型索引

多租户改造后的全部前端页面。沿用现有工作台的设计 token（绿色主色、强制浅色、白面板），将来可直接并入 app/globals.css。

主流程

① 登录→ ② 传自己的衣服 + 标印花位置→ ③ 录入需求→ ④ 出图稿→ ⑤ 出上衣效果图

「图稿生成」是 ④ 的单条快捷入口（不贴衣服）；「批量生成」把 ③④⑤ 串起来批量跑；「WPS 批量生成」是同一条链路、需求改由 WPS 原表同步。

登录 / 注册

新增
/login

手机号 + 短信验证码为主，邮箱密码为辅。含人机校验、发送频率限制说明、新账号建号事务。首次验证通过即建号，初始余额 0。

商品素材库

改造
/products

从全局共享改为每租户独立。新增配额条（款式 / 存储）、超限预警、上传入口。印花位置标定沿用现有原型。

图稿生成

重做
/artwork-studio

替代原「Logo 智能处理」。传参考图 + 七项需求 → 透明底图稿，可放大 / 抠图 / 局部修补。含预计冻结与实际结算说明、历史列表。

批量生成

重做
/batch

替代原「简单批量生图」。四列工作表：原始资料 / 需求理解（七项可改）/ 图稿制作 / 上衣效果图。需求在表格里直接加行录入（不弹窗），写入即草稿，点识别才花积分；不读 WPS。

WPS 批量生成

界面不动

现有正式生产入口，承载真实客户交付。界面与 WPS 连接层零改动，只在路由层加租户上下文与写操作拦截。内测期所有租户都能进，正式上线后下掉。

已退役

下线
/logo-studio · /workbench

/logo-studio → 302 到图稿生成；/workbench → 302 到批量生成。对应的旧 API 返回 410。

原型里刻意表达的几个约束

1. 新账号余额 0。上传浏览可以，任何付费动作直接拒绝，必须管理员发放——免费内测期防刷 API 的主闸门。
2. 冻结与结算分开显示。下单按最坏情况冻结上限，跑完按实际发生的动作结算，差额退回。UI 上必须让用户看懂这两个数。
3. 「结果未知」是独立状态。不自动退也不自动扣，保持冻结、进管理员裁定队列。对应现有「未知结果不自动重复付费」的工程原则。
4. 配额两个维度。款数和存储都要显示，因为按现有素材实测约 150 MiB/款，只限款数会被打穿。
5. 两个批量页并存。「批量生成」需求手动录入，「WPS 批量生成」需求由原表同步，下游链路完全相同。内测期都对所有租户可见；WPS 页的同步/采用新源/状态回写三个写操作限内部，因为它跑在 main 工作区、动的是客户真实交付数据。正式上线后整页下掉。
